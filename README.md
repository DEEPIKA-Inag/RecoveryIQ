# Recovery IQ

**An economic decision engine for payment recovery.**

> Razorpay's recovery agents (retry, WhatsApp, voice) all answer *"how should we recover this failed payment?"* Recovery IQ answers a different question: *"should we intervene at all, and if so, which action actually maximizes net economic value?"*

Built for the Razorpay AI Buildathon 2026 — Track: AI Revenue Recovery.

## The Problem

Every payment-recovery tool today acts the moment a payment fails — retry, nudge, call, discount. None of them ask whether that specific customer, for that specific failure, actually needs contacting. Result: wasted spend on customers who'd have self-cured anyway, and fatigue-driven churn from over-nudging others.

## The Solution

Recovery IQ predicts, for **every possible action** (including doing nothing), the probability of recovery — then picks whichever option maximizes:
net value = (amount × recovery probability) − intervention cost − customer annoyance cost

WAIT and DO_NOTHING are first-class options with real ₹ numbers attached, not fallbacks. Often, waiting wins.

| Styling | Tailwind CSS v4 |

## Architecture
Synthetic data (1,200 records) → Trained ML model → predict_probability()
│
▼
Decision engine (pure arithmetic, no ML inside)
evaluates all 8 options incl. WAIT/DO_NOTHING,
picks the highest net-value action
│
▼
FastAPI REST API → SQLite (7 tables, full audit trail)
│
▼
React dashboard

The ML model **only** predicts probabilities. All money math happens in deterministic Python arithmetic (`decision_engine/engine.py`) — every number on screen is traceable back to a probability and a configurable cost, not a black box.

## Local Setup

### Backend

```bash
cd backend
python -m venv venv
# Windows:
.\venv\Scripts\Activate.ps1
# macOS/Linux:
source venv/bin/activate

pip install -r requirements.txt

python -m app.ml.generate_synthetic_data
python -m app.ml.train_model

uvicorn app.main:app --reload --port 8000
```

Backend runs at `http://127.0.0.1:8000`. Interactive API docs at `http://127.0.0.1:8000/docs`.

### Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend runs at `http://localhost:5173` and talks to the backend automatically.

### Optional: LLM explanations

```bash
# backend/.env or shell environment
export GEMINI_API_KEY="your-key-here"
```

Without a key, the app falls back to rule-based explanations automatically — no functionality is lost.

## Why Razorpay Doesn't Already Solve This

Verified against Razorpay's Agent Studio, Intelligent Payment Retry, Failed Payment Recovery, Abandoned Cart Conversion Agent, and Subscription Recovery Agent (all publicly documented as of 2026): every one of them follows a "failure happens → agent acts" pattern. None publicly describe a pre-decision layer that treats "do nothing" as an economically competitive option. Recovery IQ is designed to sit *in front of* those agents, not replace them.
